Auto Mode Gate applies one host-neutral policy before a built-in Bash tool call executes. Version 0.1.0 blocks dangerous and ambiguous actions without invoking a model judge. The planned judge will run only after deterministic analysis for eligible cases that remain unresolved.

:::caution[Not an operating-system sandbox]
Auto Mode Gate does not replace native OpenCode or Pi permissions. A separately launched child host must load its own adapter, and coverage is limited to the documented hook paths.
:::

## How a decision works

1. The host adapter normalizes the Bash call and its available evidence.
2. The shared core applies deterministic rules.
3. A safe, exact trusted-path read may continue; dangerous or ambiguous input blocks.

| Result | Effect |
|-|-|
| `safe` | Continue when the exact configured executable path is trusted. |
| `dangerous` | Block before the host executes the call. |
| `ambiguous` | Block because the evidence or syntax is not sufficient. |

## Planned AI review

A future permission judge will receive minimal structured context only for eligible ambiguous cases. Deterministic allowances and denials will not spend a model call, and the judge will never override a deterministic denial. Errors, timeouts, invalid output, and unavailable host transport will continue to block.

## What this project protects

The gate is deliberately narrow. It does not execute commands, contact a network service, persist command text, or replace the host's native permissions. It records only sanitized decision metadata when logging is configured.
